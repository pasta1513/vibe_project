# moire

moire는 "My Outfit Identity Reflection Everyday"의 약자입니다. (D-019)

갖고 있는 옷을 등록하면 날씨와 스타일 태그에 맞춰 코디를 추천해 주고, 내가 직접 조합한 코디는 AI가 점수를 매겨 주는 웹앱입니다.

- 갖고 있는 옷 등록
- 날씨와 스타일 태그에 맞춘 코디 추천
- 내가 조합한 코디를 AI가 점수 매기기

## 현재 상태

### 화면

화면은 모두 시안(`style/html`과 사람이 준 그림)의 1536×1024 그림을 배경으로 깔고, 창 크기에 맞춰 줄어듭니다. (D-019) 메뉴바 로고를 누르면 언제든 처음 화면으로 돌아옵니다.

- **처음 열 때**: 성별 → 키 → 체형 → 확인 순서로 하나씩 골라 마네킹 모양을 정합니다.
- **처음 화면**: 방 안에 잠옷 차림 마네킹, 말풍선, 오늘 날씨 카드가 보입니다. 오늘 날짜의 코디 일기가 있으면 마네킹이 그 옷을 입고 있습니다.
- **옷장**
  - 구분별 옷 목록을 보고, 옷을 등록하고(사진 올리기, 키워드 고르기, [+ 더하기]), 상세를 보고, 선택 키워드를 고치고, 옷을 지울 수 있습니다.
  - 사진을 올리면 AI가 구분과 키워드를 미리 골라 줍니다.
  - [2D 이미지]: 무늬 표현(자동 감지, 디테일 살리기, 줄무늬 정리), 벡터 색상 수(3~10), 대표 색상만을 골라 바로 미리 보고, 옷과 함께 저장합니다. 등록한 옷은 옷 상세의 [무늬 바꾸기]로 같은 조절을 할 수 있습니다. 무늬는 화면에서 만들고 서버는 검사와 저장만 합니다. (D-021 제안)
  - [배경 고치기]: 배경색 고르기, 허용 오차, 지우기·복원 브러시, 실행 취소로 2D 이미지를 직접 고칩니다.
  - [마네킹에 입혀 보기]: 옷 종류별 틀 9개에 옷의 대표 색과 무늬(줄무늬, 데님, 벨트 등)를 넣은 캐릭터 의상을 미리 봅니다. 무늬는 틀 안에만 보입니다. (D-016)
  - [모습 조절]: 옷 상세와 등록 창에서 틀(같은 구분 안)과 옷의 위치·크기·기울기, 무늬의 위치·크기를 바꿉니다. 바꾼 모습은 마네킹이 나오는 모든 곳에 보입니다.
- **새 옷 입기**
  - 날짜(오늘 포함 5일), 지역, 태그를 고릅니다.
  - 옷을 마네킹에 직접 입혀 점수를 보거나, AI의 추천을 최대 3벌 받아 [입혀 보기]로 고칠 수 있습니다.
  - 추천받기 전에 페르소나(전문가, 친구, 즐겨찾기 기반 "내 스타일")와 요청 글(선택, 200자)을 고를 수 있습니다. 옷장에 맞는 옷이 모자라면 사면 좋을 옷을 최대 2개 함께 알려 줍니다.
  - 방 안의 거울에는 지금 입은 코디의 뒷모습이 비칩니다.
  - [확정하기]를 누르면 코디 일기에 저장되고, 날씨 배경(맑음, 비, 눈)에 확정한 옷 차림, 날씨 카드, 오늘의 코디 아이템이 보입니다.
- **코디 일기**: 3열 카드를 달별로 거르고 최신순·오래된순으로 봅니다. ⋯ 메뉴로 다시 입혀 보거나 지우고, ♡/♥로 즐겨찾기에 넣거나 뺍니다.
- **즐겨찾기**
  - 추천 카드의 하트, 점수 확인 단계, 확정한 뒤 화면의 [즐겨찾기]로도 즐겨찾기에 넣을 수 있습니다.
  - 옷걸이에서 카드를 끌어서 순서를 바꾸고, ♥로 바로 빼고, 카드를 눌러 다시 입혀 볼 수 있습니다.
- **설정**: 왼쪽 메뉴 네 개로 나뉩니다.
  - 마네킹 모양 ([설정 완료]로 저장)
  - 내 지역 (시·도 17곳, D-012)
  - 옷 키워드와 종류 단어의 성별 (비슷한 단어 확인은 AI가 합니다, D-011)
  - 스타일 태그

### AI (D-013)

- Amazon Bedrock의 Amazon Nova Lite가 다음 일을 합니다.
  - 옷 등록 때 사진을 보고 구분과 키워드 미리 고르기
  - 종류 단어의 성별 정하기
  - 비슷한 단어 판단
  - 코디 점수: 옷 키워드와 2D 이미지를 함께 봅니다.
  - 코디 추천: 옷 사진 없이 구분과 키워드만 보고 고릅니다.
- 추천의 "전문가" 페르소나만 Claude 3.5 Sonnet을 씁니다. (D-020)
- AI를 기다리는 시간은 일마다 잰 값으로 정했습니다 (API-SPEC §2.3). 시간을 넘기면 실패로 보고, 정해 둔 실패 흐름을 탑니다.
- `server/.env`의 `AI_PROVIDER`가 `fake`면 모두 가짜 AI가 답합니다. 가짜 AI일 때는 "블랙"을 더할 때만 비슷한 단어 질문이 나옵니다.

### 날씨 (D-014, D-022)

- OpenWeatherMap의 무료 5일 예보로 받습니다.
- 하루 상태(맑음, 흐림, 비, 눈)는 활동 시간(06시~21시) 예보로 고릅니다. 오늘은 지금 이후 시간만 반영합니다.
- 지역을 고르지 않았으면 날씨가 처음 필요할 때 브라우저가 위치 권한을 한 번 묻습니다. 허락하면 그 좌표의 날씨를 "부산(현재 위치)"처럼 보여 줍니다.
- 지역은 고른 지역 → 현재 위치 → 내 지역 → 서울 순서로 정합니다. 위치는 저장하지 않습니다.

### 2D 이미지화 (D-015)

- 서버에서 사진의 배경을 지운 투명 PNG를 만듭니다.

AI, 2D 이미지화, 날씨 부품은 `server/app/external/`에 있습니다.

## 시작 방법

1. README.md와 AGENTS.md부터 읽고, 앱이 무엇을 하는지, 지금 어디까지 됐는지, 어떤 규칙으로 작업하는지 확인합니다.
2. 필요한 것: Python 3.12, Node.js 22 (npm 포함). (D-008)
3. 처음 한 번 패키지를 설치합니다. 버전은 `server/requirements.txt`와 `web/package-lock.json`에 고정되어 있습니다.

```bash
cd server
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

```bash
cd web
npm install
```

## 실행 방법

### 매일 쓸 때 (D-018)

프로젝트 맨 위의 `start.bat`을 더블클릭합니다. 화면을 빌드하고 서버를 켠 뒤, 브라우저에서 http://localhost:8080 을 엽니다.
끌 때는 열린 창(검은 창)을 닫습니다.

- 빌드나 서버가 실패하면 창이 닫히지 않고 오류가 보입니다. 처음 한 번 "시작 방법"의 패키지 설치를 했는지 확인합니다.
- 바탕화면 바로가기: `start.bat`을 마우스 오른쪽 버튼으로 눌러 "바로 가기 만들기"를 고른 뒤, 만들어진 바로가기를 바탕화면으로 옮깁니다.
- 이 PC에서만 열립니다. (D-002)
- 확인 작업에서는 환경 변수 `START_NO_BROWSER=1`로 브라우저를 열지 않고, `DATA_DIR`로 다른 저장 폴더를 씁니다.

### 개발할 때 (D-008)

서버(`server/`, http://localhost:8000)와 화면(`web/`, http://localhost:5173)을 터미널 두 개에서 하나씩 켭니다. 매일 쓰는 앱(8080)과 함께 켜 둘 수 있습니다.
진짜 데이터를 건드리지 않도록, 서버를 켜기 전에 `DATA_DIR`을 `data-dev`로 둡니다 (PowerShell: `$env:DATA_DIR="data-dev"`).

```bash
cd server
.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

```bash
cd web
npm run dev
```

- 브라우저에서 http://localhost:5173 을 열면 화면이 보입니다. 화면의 `/api` 요청은 Vite 중계로 서버에 넘어갑니다.
- 서버에 요청을 직접 보내 확인할 때는 http://localhost:8000/docs 를 엽니다. (D-010)
- DB 구조는 서버를 켤 때 자동으로 최신이 됩니다 (Alembic, `server/migrations/`). 따로 명령을 치지 않습니다.
- 실패 화면을 확인하려면, 서버를 켜기 전에 환경 변수 `FAKE_FAIL`에 실패시킬 부품을 적고 서버를 다시 켭니다. 쓸 수 있는 이름은 `weather`, `recommend`, `score`, `imaging`입니다 (예: PowerShell에서 `$env:FAKE_FAIL="weather,score"`).
  - `FAKE_FAIL`은 가짜 부품에만 듣습니다. 2D 이미지화는 가짜가 따로 없어서 `imaging`을 적으면 항상 일부러 실패합니다.
  - 진짜 날씨·AI로 실패를 보려면 서버를 켤 때 환경 변수로 틀린 `OPENWEATHERMAP_API_KEY`나 `BEDROCK_MODEL_ID`를 줍니다 (TEST-PLAN §13).

### 저장 위치 (D-017)

저장 폴더는 `DATA_DIR`로 정합니다. 포트와는 상관이 없습니다. 지정하지 않으면 `data/`를 씁니다.

| 쓰는 곳 | 저장 폴더 | DB 파일 | 사진 |
| --- | --- | --- | --- |
| 매일 쓸 때 (8080) | `data/` | `data/app.db` | `data/photos/` |
| 개발할 때 (8000) | `data-dev/` | `data-dev/app.db` | `data-dev/photos/` |

- 저장 폴더는 git에 올리지 않습니다.
- 서버를 켰을 때 `app.db`가 없으면 새로 만들고, 앱 기본 단어와 태그를 넣습니다.
- 확인에 쓰는 상품 사진 2장은 `data-dev/fixtures/`에 있습니다.
- 데이터를 비우려면 서버를 끄고, 그 저장 폴더의 `app.db`(`app.db-wal`, `app.db-shm`가 있으면 함께)와 `photos/`를 지운 뒤 서버를 다시 켭니다. 지우기 전에 폴더를 복사해 두면 되돌릴 수 있습니다.

## 진짜 AI와 날씨 연결 (D-013, D-014)

설정하지 않으면 가짜 AI와 가짜 날씨로 동작합니다.

1. AWS 콘솔에서 직접 합니다. (AI는 계정 작업과 키 입력을 하지 않습니다.)
   - Amazon Bedrock 콘솔에서 Nova Lite를 쓸 수 있는지 확인합니다.
   - Bedrock API 키를 만듭니다.
2. `server/.env.example`을 `server/.env`로 복사하고 아래 값을 적습니다. `server/.env`는 git에 올라가지 않습니다. 예시 파일에는 키를 적지 않습니다. (D-004)

```
AI_PROVIDER=bedrock
AWS_BEARER_TOKEN_BEDROCK=<Bedrock API 키>
AWS_REGION=ap-northeast-2
BEDROCK_MODEL_ID=apac.amazon.nova-lite-v1:0
BEDROCK_MODEL_ID2=apac.anthropic.claude-3-5-sonnet-20241022-v2:0
WEATHER_PROVIDER=openweathermap
OPENWEATHERMAP_API_KEY=<OpenWeatherMap API 키>
```

- `AI_PROVIDER`: `bedrock`이면 진짜 AI, 없거나 `fake`면 가짜 AI입니다.
- `AWS_REGION`, `BEDROCK_MODEL_ID`: 적지 않으면 위의 값을 씁니다. 서울은 Nova Lite를 바로 쓸 수 없어 아시아·태평양 묶음(`apac.`)으로 부릅니다. 요청은 도쿄, 서울, 오사카, 뭄바이, 싱가포르, 시드니 중 한 곳에서 처리될 수 있습니다.
- `BEDROCK_MODEL_ID2`: 추천의 "전문가" 페르소나에만 쓰는 모델입니다 (D-020). 비우면 전문가도 `BEDROCK_MODEL_ID`를 씁니다. Claude 모델을 쓰려면 AWS 콘솔에서 계정의 Anthropic 사용 목적 양식을 한 번 내야 합니다. 서울에서는 아시아·태평양(`apac.`) 모델만 씁니다.
- `WEATHER_PROVIDER`: `openweathermap`이면 진짜 날씨(무료 5 Day / 3 Hour Forecast), 없거나 `fake`면 가짜 날씨입니다.
- `OPENWEATHERMAP_API_KEY`: 날씨에 쓸 키입니다. `WEATHER_PROVIDER=openweathermap`일 때만 씁니다.
- 값을 바꾼 뒤에는 서버를 다시 켭니다.
